# STR PMS research and Yellow handoff

Checked against current official sources on 1 October 2026. This is a bounded first cohort of twelve products, with an additional hybrid/distribution cohort in progress. It is not a claim that every STR PMS has been researched or that Yellow already implements each feature. Research is retained outside Yellow; the authorised cloud build owns governed Yellow implementation.

## User's accepted product direction

Registration offers **Hotel / STR / Both**. Login supports the Hotel and STR workspaces through the same identity. Users with both retain a **Hotel / STR switch in Yellow's main ribbon**. Workspace choice changes presentation and authorised portfolio filters, never permissions or inventory authority. CRM for operational task distribution is the cloud's immediate priority; the earlier PMS/CRS priority was corrected by the user.

## Integration requirements forwarded to cloud

1. Keep organisation, physical property/building, sellable unit and channel listing distinct. A unit offered on several OTAs has one occupancy source. Parent/child and pooled inventory must reuse Yellow's governed constraints.
2. Reuse identity, reservations, stays, guest/party, payment, finance and tasks; add capability-driven views rather than a second PMS or copied domain logic.
3. Hotel view prioritises room board, arrivals/departures, front desk, housekeeping and cashier. STR view prioritises portfolio/unit calendar, turnover/inspection/maintenance, remote arrival/access instructions, channel mapping and owner operations. Preserve controlled detail under simple primary actions.
4. Tasks need assignment, acceptance, due times, escalation, reassignments, completion receipts/history and property-scoped worker access. Presentation must invoke existing authorised domain commands.
5. Separate owner contracts/commissions/statements, actual payouts, client-money/trust accounting and operating accounting. Never call a reporting page a trust ledger.
6. Before activating a channel connection, review imported future bookings, rates, fees/taxes, policies and unit/listing mappings; API connectivity and iCal are different capabilities.
7. Validate hotel-only, STR-only and mixed portfolios; inaccessible/foreign/revoked property scopes; direct-link workspace forgery; switch during in-flight mutations; mobile ribbon behavior; the required real-database invariants and browser acceptance.
