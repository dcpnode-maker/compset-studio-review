# Dual workspace contract — Orders013,016 and020

The STR and hotel views consume saved evidence through lazy read-only endpoints. They share the accepted collection controller and keep collection scope separate from display filters. The existing static application remains the integration shell. The contract below describes the implemented source; live activation and visual QA remain separate acceptance steps.

## Lazy API

The existing `/api/workspace` contract remains for the legacy rate view. The new interface requests compact summaries first, never all annual calendars or every subject's candidate audit.

| Route | Bounded response |
| --- | --- |
| `GET /api/intelligence` | Schema version, source timestamps, coverage summary, subject headers, collection targets and warnings; no calendar cells or full candidate audits. |
| `GET /api/intelligence/str/calendar?start=YYYY-MM-DD&days=14&city=Dubai&offset=0&limit=25` | Validated returned request context, matching property count, dates, a bounded property page and its date cells. Search/bedroom filters are saved-data view filters. |
| `GET /api/intelligence/str/compset?subject_id=bnbme_direct%3A...&offset=0&limit=25` | One namespaced subject's criteria, summary and adaptive steps, with a page of merged candidate profiles and decisions. Compact `map_points` retain all observed candidate locations. |
| `GET /api/intelligence/hotel` | Aketa's saved source/date rates plus its separate researched product/service competitor set. Source/date/offer filters are local where the payload is small. |

Responses include a source revision; calendar and comparison responses also echo normalized request context. Frontend request sequence and context guards reject responses from an older property, date window, mode or filter selection. A changed source revision requires saved-data reload before mixing data. Reload invalidates the URL/context cache. Missing artifacts produce explicit incomplete coverage.

Order016 adds a bounded 24-entry least-recently-used cache for validated view responses. In-flight GETs are coalesced by exact URL, with separate summary/view/detail ownership. Replacing a consumer's request aborts its previous transport only when no owner remains; explicit reload/destroy invalidates and aborts the whole generation. Accepting a reloaded summary also cancels intervening view/detail reads and clears their cache, so navigation while the summary is pending cannot retain the previous source revision. Aborted reads cannot populate the cache or paint errors/results after their consumer has moved on, including when cancellation happens during JSON decoding. A stale promise's cleanup cannot remove a newer same-URL request. Browsers without `AbortController` still retain sequence/revision/context rejection. Failed reads are not cached. Cached navigation avoids an unnecessary loading/empty render. New uncached filter contexts remain explicitly loading rather than presenting rows from a different context.

Calendar accepts `city`, `currency`, `query` (maximum 120 characters), `bedrooms` (including zero), and `namespace` before pagination. Default namespace is `bnbme_direct`; the HTTP route maps `namespace=all` to no namespace filter. Limits are 31 dates and 25 properties. The UI normally requests 14 dates and 25 properties. Comparison supports `decision` and `candidate_id` before pagination; its limit is at most 100 and the UI requests 25. Map clicks use `candidate_id` to load one full audit. `candidate_total` reports the filtered population; `all_candidate_total` retains the original population.

Projection requirements:

- Summary: `{schema_version,revision,observed_at,str:{properties,subjects,summary,default_start,calendar_bounds},hotel,warnings}`. Namespaced property headers retain title, city, bedrooms, bathrooms, capacity, coordinates, source URL, currency and original attribute time. The observed 113 direct-site and 60 unlinked Airbnb records remain separate; these counts are data, never hardcoded UI values.
- Calendar: `{revision,request,total,dates,entities,cells,summary,source_context,warnings}`. There is no portfolio-wide currency conversion or aggregated price. Invariant guest/tax/fee context is inherited from `source_context`, rather than duplicated in every direct-site offer.
- Comparison: `{revision,request,subject,criteria,summary,adaptive,candidate_total,all_candidate_total,candidates,map_points,warnings}`. Keep reasons, missing fields and original source times. Physical similarity does not establish a direct-site/Airbnb identity link.
- Hotel: `{revision,dataset,compset,portfolio,warnings}`. The Aketa dataset retains existing safe rate semantics. Its separate researched candidates retain product/service evidence, coordinates, distance, inner-five-kilometre band and missing fields. Research profiles are not dated offers. Optional imported Lighthouse profiles also appear under summary `hotel.portfolio`.

Use the existing Cell fields (`entity_id`, `date`, `checkout`, `state`, `amount`, `display_amount`, `currency`, `precision`, `amount_basis`, `observed_at`, `reason`, `offers`). Direct-site cells additionally retain `availability` (`available`, `unavailable`, `unknown`) independently of rate evidence. Available inventory without a price displays **Available · price unknown**. A website calendar rate is labelled as such, never promoted to a verified stay quote. Missing, restricted and unavailable states never become zero. Both refundable and non-refundable options retain their source basis and conditions in details.

The API projection must not expose credentials, raw response bodies, local artifact paths or unfiltered arbitrary fields. Every public link passes the existing safe-public-URL rules. Generated time is not observation time. Source currency, party and amount basis are retained when displaying or exporting any rate.

## Collection bridge

`CompSetRates.mountCollection(root, {datasetId, onReload})` reuses the existing controller with a collection-only renderer. It returns `{ready,setDataset,refresh,destroy}`. Mount reads only `/api/workspace/job`, and never invokes the initial callback or requests `/api/workspace`. Refresh and a matching terminal job invoke `onReload` to reload the lazy views. The existing default mount remains compatible.

The dual workspace mounts one persistent collection dock. Mode/property/filter/date navigation only changes the viewed evidence. `setDataset` changes the target of a future explicit fresh action; it never changes an active job or the frozen target of Resume. Fresh and pause retain the accepted GET-preflight, request headers, sequence guards, shared ownership, cooperative pause, cooldown handling and fixed job identity. Mount, navigation, polling and saved-data reload perform no POST.

Only `aketa` and `airbnb-compset` are current collection targets. The STR dock explicitly says **Saved Dubai Airbnb comparison set**; it must not imply that the fresh action refreshes all 113 direct-site properties or the property currently selected in the portfolio calendar. Unsupported direct-property collection remains a truthful scope note, not a cosmetic sync control. The full collection contract remains authoritative in `docs/workspace-collection-contract.md`.

Imported hotel profiles have no automatic rate-dataset link. Choosing one calls `setDataset(null)`, which disables a new fresh collection while retaining any existing job's identity, pause and resume. Their rate view and CSV retain the imported profile and explicit rate-coverage gap. Choosing Aketa or STR restores the relevant supported fresh target.

Imported hotels may expose saved configured competitor names through `hotel.portfolio.configured_labels`: `{status,groups:[{subject_id,competitor_labels,identity_status,observed_at,source_url}],observed_membership_count,verified_competitor_id_count,rates_collected_count,warnings}`. A comparison view displays only the one group whose `subject_id` exactly equals the selected profile ID, and only with `status=observed_name_only` and `identity_status=name_only_unresolved`. Names are plain labels, never selectable or verified OTA identities. Membership observation time and source remain visible. No prices, coordinates or distances are inferred; imported-hotel maps explicitly report missing locations. Comparison CSV preserves selected subject ID/title, configured name, observation/identity status, uncollected rate status, original timestamp and safe source URL, with spreadsheet formula guards.

Summary profile `configured_label_count` is nullable and accompanied by `configured_label_status`. Missing groups, failed reads and unknown counts show a dash/unknown coverage. An explicitly observed empty group is zero. A loaded valid group supplies its own count. These groups do not enable collection or change an existing job.

## View behavior

Order022 adds a local market editor to the same saved-evidence contract. The STR map keeps the Order020 circle and adds a polygon draft with pointer/touch vertex entry, preview, vertex editing, coordinate-entry fallback, Undo, Apply, Cancel and Clear. A visible candidate rail follows the committed area and pages through all located saved candidates. Its local Include selection, markers, metrics and map-view CSV agree; the underlying saved match decision remains an audited source fact. Named sets use browser-local storage scoped by mode, subject and source revision. Older-revision sets cannot silently redefine membership after a saved-data reload. Geometry and local selection do not start collection or write a backend compset. Missing coordinates remain outside the geometric count and are reported separately.

The hotel workbench now shows every saved source/offer on a date in the calendar's visible source lines and its full detail inspector. Its dense rate table has one row per recorded offer, search, source/room/meal/cancellation filters, date/source/observation sort and selectable information columns. The rate basis, stay context, tax/fee and payment fields appear when actually observed; missing evidence reads Unknown. Multiple offers are separate rows, and a filtered offer does not inherit the unfiltered cell minimum. Calendar and table share the original source, date, party, currency and observed-time context. Imported name-only hotel profiles still have no rate dataset.

STR mode presents a compact portfolio filter bar, sticky property and date headings, a multicalendar, a per-property comparison list and a geographic view using observed coordinates. City, bedrooms and property search operate on saved data before pagination. Date navigation retains selected property and filter state. Map selection does not start discovery. An edited radius is a local map view and leaves saved match decisions intact. Desktop uses dense comparison tables; mobile defaults to a day/list view, bottom navigation, a tall map in normal page flow and detail sheets, with controls at least 44 pixels high.

The 760px breakpoint selects which calendar tree is constructed. Mobile creates only selected-day property rows; desktop creates only the bounded multicalendar. Changing a mobile day updates that list without reconstructing the toolbar, navigation or hidden desktop cells. Breakpoint changes rebuild the active representation from the same saved payload and preserve selection without another read. Mobile calendar CSV contains the displayed day/property page; desktop CSV contains the displayed date window/property page. Neither export changes source context.

The map instance, tile layer and selected zoom survive radius/center edits and responsive breakpoint changes. The circle and center marker move in place; candidate marker membership is reconciled and popup content is created on demand. These interactions do not perform intelligence reads. Leaving the map, changing its source identity/revision or destroying the controller releases the instance. Removed map callbacks cannot retarget a later map. Selecting a different subject resets its local center, and STR centers never leak into hotel maps. If a reload removes the selected subject, its replacement starts with its own observed center, default radius and first candidate page.

Order020 adds explicit Draw area, Move center and Resize area actions using captured mouse/touch/pen pointers. The first point is the circle center and the release point sets its radius; minimum movement is 8px and supported radius is 0.1–50 km. Direct center/edge handles have pre-gesture `touch-action:none`; the map consumes gestures only while an edit is armed. Existing Leaflet classes survive mode updates. Committed center/radius remain distinct from preview geometry; CSV uses the committed selection. Escape/Cancel, pointer cancellation/capture loss, a second pointer, window blur, hidden document and teardown cancel the preview and restore each map handler's prior enabled state. A failed capture leaves the labelled numeric/range controls usable. Ordinary map clicks preserve the circle.

The area summary reports only observed candidate coordinates, saved selected/provisional decisions, missing decision evidence and omitted unlocated candidates under the current saved-decision filter. Candidate lists and evidence use the same geographic selection. No unknown rate, unavailable date, complete market size, occupancy or market price is inferred from an area gesture. No collection POST is issued by drawing/moving/resizing.

Hotel mode presents Aketa's saved rate-shop calendar and table, observation-source controls, and a separate product/service competitor workflow. Room, meal and cancellation controls filter recorded offers only when that field is present. Guests and length of stay describe the frozen saved context; unsupported request changes do not imply a new rate shop. No market median, occupancy, revenue or recommendation is synthesized from missing or incompatible evidence.

Hotel mobile calendar uses a day selector and one readable row per filtered source, showing its own amount/currency, evidence state, stay, amount basis and observation time. This replaces the tiny seven-column mobile month layout; the desktop month view and explicit all-date table remain available. Hotel day selection is separate from STR day selection. Source and offer filters intersect the displayed day. Mobile calendar CSV exports the displayed day/source rows, while the all-date table exports its full filtered scope. Imported profiles remain isolated from Aketa's data and do not gain collection or rate coverage from this change.

Cell details show the exact stay, source, observation time, availability or restriction evidence, room/rate options, tax/fee inclusion, membership/coupon conditions and actual party context. Candidate details show reasons and evidence gaps. CSV exports match the visible page or map view and retain provenance/context; spreadsheet formula prefixes are guarded. Unknown values remain blank or explicitly unknown. `Collection tools` calls the root shell's `CompSetOpenTools()` only after a user click.

At 1150px and below the inspector acts as a modal overlay: background regions become inert/hidden to assistive navigation, enabled visible controls contain Tab/Shift+Tab focus, and Escape closes it. Above that breakpoint the inspector remains nonmodal. Closing restores a connected opener, or a connected header action if the opener was removed. Saved reload releases the modal state and supplies a connected focus fallback. Loading a candidate's full audit retains the original opener. No browser/device screen-reader verification is implied by the offline keyboard fixture.
