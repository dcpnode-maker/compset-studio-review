# Workspace collection API contract

`POST /api/workspace/collect` accepts only `{dataset_id: "aketa" | "airbnb-compset", mode: "fresh" | "resume"}` (mode defaults to fresh). The entire saved dataset is collected; display filters do not change request context. Unknown fields are rejected. Successful start is HTTP 202 with a Job object; an active collector returns 409. Missing or unsupported dataset context returns 400. The server chooses dates, budgets and configured source adapters.

`GET /api/workspace/job` returns a Job, or `{state:"idle",job_id:null}`. It does not launch work. `POST /api/workspace/pause` accepts only `{job_id: <current job id>}` and returns 202 with the Job carrying `pause_requested:true`; wrong or inactive job IDs return 409. Both POSTs use `Content-Type: application/json` and `X-CompSet-Request: dashboard-v1`, with existing local Host/Origin validation. Status GET has the same local guards and no-store behavior as workspace GET.

Job keys: `{job_id,dataset_id,mode,state,phase,message,started_at,updated_at,finished_at,pause_requested,context,progress}`. Optional keys can be null. State is `idle`, `running`, `paused`, `partial`, `complete`, `stopped`, `failed` or `interrupted`. Phase is a human-readable string identifying planning/calendars/prices/finalization. Progress is a safe object of counts/budgets/coverage, never raw source responses, command lines or file paths. Context includes actual dates, currency, guests and rooms where appropriate. Only `running` means active. `complete` must not imply complete pricing if unknown cells remain; message and progress report coverage explicitly.

UI mounts with GET workspace and GET job, polls job every three seconds while active, and automatically reloads saved workspace evidence when its observed active job ends. It disables concurrent starts, exposes cooperative pause and explicit Resume collection for paused/partial jobs, and keeps job dataset/context visible across view changes. Fetch fresh data always sends mode fresh. Reload saved data remains a separate read-only action. A 404 shows that the updated local service must be restarted; it is not a successful collection. A blocked or stopped source must not trigger an automatic retry.

`busy` is true for any active dashboard collector. Workspace jobs expose `pause_supported:true` while running. An active legacy collector returns a separate status with `state:"running"`, `job_id:null`, `dataset_id:null`, `phase:"legacy collection"`, `busy:true`, `pause_supported:false`, `legacy:true` and empty progress; it never reuses a previous workspace job's progress. Legacy controls and workspace starts acquire the same persisted local lease. A dead worker becomes `interrupted`; reading status does not start or retry it.

Fresh collection freezes dates and membership when accepted. Aketa uses the next 30 Asia/Kolkata dates, one adult, one room, no children and INR, with at most eight source-adapter captures. Airbnb uses the next 30 Asia/Dubai dates, the saved subject plus at most 100 selected competitors, one adult and no children, infants or pets, retaining the explicit saved currency. Its budgets are 100 direct calendar reads and 100 direct quote reads; each phase may additionally perform one browser bootstrap and up to eight observed-request reads, reported separately. Source starts are paced by at least three seconds. The subprocess has a one-hour time limit and checks for cooperative pause between operations.

Fresh mode bypasses validated healthy positive and verified-unavailable caches, because prices and inventory can change. Resume reuses validated observations within six hours. Both modes preserve a six-hour cooldown after source access, transport or schema failure; a fresh button does not bypass a challenge or rate limit. A stopped, paused or incomplete calendar phase cannot start quote transport: it may only publish a no-network current-window checkpoint with existing verified quotes retaining their original source timestamps. The newly collected subject calendar is explicitly passed into quote preflight, ahead of older legacy subject reports.

Resume requires the latest resumable job for that dataset and binds to its frozen context and selected-listing snapshot. It receives a new job ID; changing the saved comparison set cannot silently retarget it. An expired date window or missing saved plan is HTTP 400 and requires an explicit fresh collection. Job-specific progress is saved under that new identity. Before-refresh reports are retained in the job folder, while source and interpretation history keep their existing append-only storage. Worker completion, budget completion and complete price coverage remain separate states.
